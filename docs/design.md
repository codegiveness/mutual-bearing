# Mutual Bearing architecture

Mutual Bearing is a standalone collaboration ecosystem, not a prompt-rewriting wrapper or a bundle of competing instruction sets. [GUIDANCE.md](../GUIDANCE.md) remains the single canonical and complete behavioral policy. The standard distribution combines that policy with first-party setup and repair skills; this document explains their boundaries and adds no runtime rules.

## The transformation is an effective understanding

The input is a user message in conversational context. The useful transformation is the agent's revised understanding and next appropriate action—not necessarily a new text string. Preserve the original message while relating it to goals, evidence, constraints, decisions, uncertainty, and authority.

Every delivered message participates. A clear request can go straight to execution. A brief continuation can rely on earlier choices. A correction can invalidate pending work. A question, exploration, or requested plan can be a complete task. Universal attention does not require a universal visible process or a more elaborate prompt from the human.

Autonomous mutual bearing means taking responsibility for the authorized work and its continuity while keeping consequential interpretations recognizable and revisable. It does not mean deciding human-owned goals, manufacturing agreement, or requiring approval at every already-authorized step.

## One kit, one behavioral authority

| Layer | Owns | Does not own |
|---|---|---|
| Persistent guidance | Contextual interpretation, bounded autonomy, evidence, completion, repair, and continuity. | Host delivery, tool capabilities, or a guarantee of correctness. |
| Setup skill | Explicit project integration, configuration checks, updates, removal, and loading diagnosis. | Silent installation during unrelated tasks or changing user-global configuration. |
| Repair skill | Focused diagnosis when requested or when a mismatch's cause or remedy remains unresolved. | A second policy, persistent mode, or mandatory detour for clear corrections. |
| Ordinary prompts | Current human goals, context, constraints, delegation, and feedback. | A requirement to supply a perfect brief or activate every behavior manually. |
| Host | Instruction and skill discovery, context preservation, message delivery, and tools. | Proof that a good artifact establishes human agreement or permission. |

Skills are included in the default installation, but loaded selectively. Fundamental responsibilities remain available without skill discovery: a missing method must not make the agent forget context, invent evidence, or exceed authority. This is resilience, not a competing guidance-only adoption product.

The setup skill carries a generated byte-identical resource from `GUIDANCE.md` because skill installers copy individual skill directories, not arbitrary repository-root files. `scripts/sync-guidance.mjs` maintains that resource; `--check` detects drift. There is one authored policy, not two independently edited versions.

## Orchestration follows the work

Persistent guidance connects requests, resources, and decisions without an obligatory chain of skills. Select a skill by the requested work and the actual unresolved need, not by keywords in source material. Keep metadata short and load supporting material only when relevant.

- Direct work remains direct when the task is clear.
- Accessible facts are recovered or investigated before asking the human to repeat them.
- An unresolved consequential choice is exposed before the dependent commitment; independent authorized work can continue.
- An evident correction changes affected work immediately, preserving unaffected choices.
- Requested or unresolved collaboration diagnosis can use the repair method, then return to the task.
- Setup is restricted to installation, update, removal, or a loading problem.
- Prompt composition is selected when a prompt is the desired artifact. An independently installed prompt-design skill may help, but is not required or invoked merely because the task concerns instructions.

No central background service, automatic prompt replacement, mandatory prompt editor, or external skill dependency is introduced. The agent carries the orchestration in its working understanding, conversation, and existing task state.

## Alternatives and tradeoffs

| Design | Tradeoff | Decision |
|---|---|---|
| Guidance plus an optional add-on | Simple core adoption, but presents the focused methods as outside the product. | Superseded as the standard installation contract. |
| Skills alone | Small discovery metadata, but general responsibilities can fall between triggers or disappear after context loss. | Not the automatic foundation. |
| Guidance plus bundled focused skills | One behavioral policy, first-class methods, selective context use, and explicit setup. | Standard kit. |
| A compulsory multi-skill pipeline | Predictable stages at the cost of needless reads, misrouting, and premature prompt rewriting. | Rejected. |
| Custom production hooks or a runtime orchestrator | Can bridge a demonstrated delivery gap, but adds host-specific timing, precedence, and cancellation obligations. | Not needed for this installation; use native documented discovery. |

## Quality without blame or guarantees

The outcome to improve is the work: supported claims, complete deliverables, correct reasoning, proportionate scope, calibrated confidence, respected context and authority, and corrections that reach artifacts. A label such as “lazy” identifies neither a cause nor a remedy. The [repair explanation](diagnosis.md) distinguishes interpretation, evidence, capability, authority, and execution failures without treating that list as exhaustive.

Human goals, examples, feedback, and delegation affect what can be achieved. The agent should help develop useful context, not demand perfect input or assign failures to the human. Model and environment limits remain real. More instructions, more agreement, and more autonomous activity are not themselves evidence of better output.

## Continuity and evidence

Carry relevant goals, settled and proposed choices, reasons, permissions, uncertainty, and work status through follow-ups, handoffs, and resume. Use the conversation or existing task state rather than introducing a hidden profile or mandatory ledger. A later answer settles what it addresses; it does not authorize every earlier proposal.

The [evaluation](../evaluation/README.md) retains a primary no-skills condition and adds the full kit and a baseline. It inspects actual artifacts and raw responses, including unfavorable outcomes and differences in interaction burden. [Integration](integration.md) separately establishes what the host loads. A bounded successful exercise cannot prove universal awareness, flawless outputs, automatic interruption, or human agreement.
